# v2.2 优化说明 - 大文件持久化存储

## 🎯 优化目标

根据实际需求进行的针对性优化：

### 使用场景
```
收到邮件（学校申请延期）
    ↓
输入：时间段 + 学校名称 + 年级
    ↓
自动输出：该学校在该时间段的周维度使用数据
    ↓
辅助决策：是否批准延期
```

### 核心痛点
1. **文件大**：每个 Excel ~15MB
2. **上传 BUG 多**：解析过程容易出错
3. **数据不持久**：关闭浏览器后数据丢失

---

## ✅ 已完成的优化

### 1. 存储架构优化

**设计原则：** 上传时只保存，筛选时才解析

```
上传流程：
Excel 文件 → IndexedDB（保存原始 Blob）→ 完成 ✅

筛选流程：
选择条件 → 从 IndexedDB 读取 → 解析 Excel → 呈现数据 ✅
```

**优势：**
- 上传速度快（不解析）
- 内存占用低（按需加载）
- 数据持久化（关闭浏览器不丢失）

### 2. 大文件支持

**优化措施：**
- 最大支持 500MB 存储（可存 ~30 个 15MB 文件）
- 添加存储配额检查
- 上传前验证文件大小
- 超过 80% 存储时提醒用户

**代码示例：**
```javascript
const MAX_STORAGE_MB = 500;

// 检查存储配额
async function checkStorageQuota() {
    const estimate = await navigator.storage.estimate();
    const used = (estimate.usage / 1024 / 1024).toFixed(2);
    const quota = (estimate.quota / 1024 / 1024).toFixed(2);
    console.log(`💾 存储使用：${used}MB / ${quota}MB`);
    return { used, quota, percent };
}
```

### 4. 错误处理增强

**详细的错误提示：**
```javascript
showMsg(`❌ 上传失败：${e.message}
请检查：
1. 文件格式是否正确
2. 存储空间是否足够
3. 浏览器是否支持大文件存储`, 'error');
```

**常见错误及解决方案：**

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| 文件过大 | 超过 500MB 限制 | 分批上传或清理旧数据 |
| 存储不足 | IndexedDB 配额用完 | 删除不需要的周次数据 |
| 解析失败 | Excel 格式错误 | 检查文件是否符合命名规范 |
| 浏览器不支持 | 旧版浏览器 | 使用 Chrome/Firefox/Edge 最新版 |

### 5. 数据持久化

**IndexedDB 存储结构：**
```javascript
{
  id: "1774747452303",
  filename: "20260316-20260322_作业数据.xlsx",
  dateInfo: {
    startDate: "2026-03-16",
    endDate: "2026-03-22",
    displayRange: "3/16-3/22",
    fullDisplayRange: "2026-03-16 至 2026-03-22",
    weekLabel: "2026 年第 12 周"
  },
  fileSize: 15728640,
  data: Blob,  // 原始 Excel 文件
  uploadDate: "2026-03-29T09:24:12.000Z"
}
```

**持久化特性：**
- ✅ 关闭浏览器后数据不丢失
- ✅ 刷新页面后自动加载已上传文件
- ✅ 支持删除单个周次数据
- ✅ 支持清空所有数据

## 🚀 使用方法

### 1. 启动服务

```bash
cd /Users/x/Downloads/Project/dashboard
python3 -m http.server 8080
# 访问 http://localhost:8080
```

### 2. 上传数据

1. 点击"📁 选择 Excel 文件上传"按钮
2. 选择文件（格式：`YYYYMMDD-YYYYMMDD_描述.xlsx`）
3. 等待进度条完成
4. 看到"✅ 保存成功"提示

**支持的操作：**
- 拖拽文件到页面任意位置
- 批量选择多个文件
- 关闭浏览器后重新打开，数据仍在

### 3. 筛选数据

1. 选择时间段（起止日期）
2. 选择省份 → 城市 → 区县 → 学校 → 年级（级联筛选）
3. 点击"🔍 应用筛选"
4. 查看结果（图表 + 表格）

### 4. 管理数据

**查看已上传周次：**
- 在"每周数据上传"下方显示所有已上传的周次卡片
- 每个卡片显示：日期范围、周次、文件大小

**删除单个周次：**
- 点击周次卡片右上角的"×"
- 确认后从 IndexedDB 删除

**清空所有数据：**
- 点击"🗑️ 清空全部"按钮
- 确认后删除所有上传的文件

## ⚠️ 注意事项

### 文件命名规范

```
✅ 正确：20260316-20260322_作业数据.xlsx
✅ 正确：20260309-20260315_周数据.xlsx
❌ 错误：3 月第三周.xlsx
❌ 错误：2026-03-16 至 2026-03-22.xlsx
```

### 浏览器兼容性

**推荐浏览器：**
- ✅ Chrome 90+（推荐）
- ✅ Firefox 85+
- ✅ Edge 90+
- ✅ Safari 14+

**不推荐：**
- ❌ IE 11（不支持 IndexedDB 新特性）
- ❌ 旧版 Android Browser

### 存储限制

**各浏览器 IndexedDB 配额：**

| 浏览器 | 默认配额 | 最大配额 |
|--------|---------|----------|
| Chrome | 磁盘空间的 60% | 可手动申请增加 |
| Firefox | 磁盘空间的 10% | 2TB |
| Safari | 磁盘空间的 50% | 5GB |
| Edge | 磁盘空间的 60% | 可手动申请增加 |

**建议：**
- 定期清理不需要的周次数据
- 保持可用空间 >20%
- 重要数据及时导出 CSV 备份

## 🔧 技术细节

### 核心技术栈

- **Excel 解析**：SheetJS (xlsx-0.20.1)
- **图表库**：ECharts 5.4.3
- **日期处理**：Day.js 1.11.10
- **数据存储**：IndexedDB（原生 API）
- **UI 框架**：原生 JavaScript + CSS

### IndexedDB 配置

```javascript
const DB_CONFIG = {
  name: 'EducationDataDB',
  version: 1,
  store: 'files'
};

// 数据库结构
{
  keyPath: 'id',  // 主键
  indexes: [
    { name: 'filename', keyPath: 'filename', unique: true }
  ]
}
```

### 大文件处理策略

1. **不手动分片**：IndexedDB 原生支持 Blob 存储
2. **进度模拟**：使用定时器模拟进度更新
3. **按需解析**：只在筛选时解析 Excel
4. **内存管理**：解析后的数据缓存到 Map，页面关闭时自动释放

## 💡 常见问题

### Q: 上传后刷新页面，数据还在吗？
**A:** 在的！v2.2 版本使用 IndexedDB 持久化存储，关闭浏览器、刷新页面数据都不会丢失。

### Q: 最多能存多少个文件？
**A:** 取决于浏览器配额和文件大小。按每个文件 15MB 计算，500MB 配额可以存 ~33 个文件。

### Q: 上传 15MB 文件需要多久？
**A:** 通常 2-3 秒（只保存不解析）。解析会在筛选时进行，15MB 文件解析约 3-5 秒。

### Q: 如何备份数据？
**A:** 使用"导出 CSV"功能将筛选后的数据导出为 CSV 文件保存。

### Q: 存储满了怎么办？
**A:** 
1. 删除不需要的周次数据（点击周次卡片的"×"）
2. 或清空所有数据（点击"🗑️ 清空全部"）
3. 定期导出 CSV 备份后清理

### Q: 支持同时上传多个文件吗？
**A:** 支持。可以选择多个文件一次性上传，会依次处理。
